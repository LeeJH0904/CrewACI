# 논문 구성 가이드

갱신일: 2026-09-04

## 1. 중심 주장: 기본과 확장을 분리

기본 원고는 다음 연구를 설명한다.

> ACIArena 공개 Math·Code 부분집합에 제한된 CrewAI Sequential 구성을 재구현하고, 선택한 CrewAI 기능의 대응 및 ACIArena 공격 계약의 실제 작동을 검증한 뒤, 고정 구성의 utility와 ACI 공격 성공률을 평가한다.

이는 작성 방향이며 아직 완료된 실험 결과를 뜻하지 않는다. 실제 수행한 내용만 결과형 문장으로 바꾼다. Hierarchical을 채택·검증하고 동일 조건 비교를 수행한 경우에만 “두 Process 비교”를 중심 주장에 추가한다.

## 2. 신청서·선행연구와의 관계

- 신청서의 1,356 사례 목표와 공개 Math·Code 69개 task, 본 연구 run 수를 다른 단위로 설명한다.
- 2026-08-31 범위 축소와 2026-09-04 Sequential 우선 결정을 Methods 또는 Limitations에 남긴다. Hierarchical 미진행이면 판단 근거와 미수행 연구 질문을 명시한다.
- 기존 6종 MAS와의 전면 비교, PVI, delegation 등 신청서와 달라진 항목은 실제 수행 범위를 숨기지 않는다. 단순 회귀 smoke test를 MAS 간 정량 비교라고 부르지 않는다.
- 기존 조사 문서의 ACIArena·CASPIAN·TAMAS 정리는 원문·공개 코드·버전을 최종 확인해 인용한다. “최초 CrewAI 적용”은 주장하지 않는다.
- 기본 기여는 재현 가능한 통합, 기능/공격 계약 검증, 주입 증거가 남는 평가다. 새로운 공격이나 방어 알고리즘을 제안한 것처럼 표현하지 않는다.

배경 검토 출발점: [선행연구조사](../../선행연구조사/ACIArena_CrewAI_선행연구조사.md), [ACIArena 논문·구현 비교](../../../ACIArena_관련_문서/ACIArena_논문_구현_비교.md).

## 4. 최소 표와 그림

필수 표는 기능·공격 계약 대응/검증 상태, native 대조 결과, domain별 BU, 공격별 UA·ASR·유효 분모, 미호출·미주입·오류·비용 요약이다. Hierarchical을 수행한 경우에만 구성 비교 표를 추가한다.

그림은 통합 구조와 실제 메시지/공격 적용 경로를 우선한다. 복잡한 전파 그래프나 heatmap은 그 그림으로만 설명할 수 있는 결과가 있을 때 사용한다. 직접 주입 표지를 의미적 전파 성공 표지처럼 그리지 않는다.

## 5. 해석·주장 규칙

1. 기본 결과는 고정된 Sequential 재구현의 결과다. CrewAI 전체 애플리케이션이나 공식 runtime 전체로 일반화하지 않는다.
2. native calibration은 작은 표본의 기능 대조이며 완전 동등성 증명이 아니다. 구조적 차이를 구체적으로 공개한다.
3. 낮은 ASR과 높은 오류율·낮은 BU·미주입을 구별한다. 분모가 다른 논문 수치를 직접 우열 비교하지 않는다.
4. 공격 범주·표면이 교차하지 않은 결과를 표면만의 효과라고 주장하지 않는다.
5. Hierarchical 차이는 Manager·호출 수·프롬프트를 포함한 Process 차이다. 단순 topology 인과 효과라고 단정하지 않는다.
6. PVI를 산출하지 않았으면 조건 미충족과 사유를 밝힌다. 로그 존재만으로 전파 취약성을 정량화했다고 하지 않는다.
7. subset의 확인 반복을 전체 matrix 반복으로 표현하지 않는다. 유리한 결과에 따른 task·공격·구성 선택을 하지 않는다.

## 6. 제목과 초록 작성 원칙

기본 제목 예: **A Reproducible ACIArena Integration for Evaluating a CrewAI-style Sequential System**.

확장 제목 예: **Evaluating Sequential and Hierarchical CrewAI-style Systems under Agent Cascading Injection**. 두 구성의 실제 검증·비교가 없으면 사용하지 않는다.

초록에는 문제와 제한된 범위, 통합·검증 방법, 실제 데이터·구성, 확인된 수치, 한계를 순서대로 쓴다. 결과가 없으면 빈칸을 사실처럼 채우지 않는다. “최초”, “공식 CrewAI와 동일”, “1,356개 전체 재현”, “CrewAI는 다른 MAS보다 안전”은 해당 근거 없이 사용하지 않는다.
