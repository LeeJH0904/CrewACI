# 연구 목표 및 기여

갱신일: 2026-09-04

## 1. 연구 목적과 출처의 구분

CrewAI의 제한된 Sequential 구성을 ACIArena 내부 추상화로 재구현하고, 기존 공격 계약과 평가 파이프라인에 연결해 ACI 취약성과 정상 작업 성능을 측정한다. Sequential 구현·검증·소규모 파일럿을 먼저 완료한 뒤 Hierarchical 구현 여부를 결정한다. Hierarchical은 현재 확정 구현 범위가 아니다.

- **ACIArena에서 준용:** `BaseMAS` 실행 인터페이스, `BaseAgent.run_step()` 공격 훅, 기존 task/attack verifier.
- **CrewAI에서 준용:** role·goal·backstory, Task context, Sequential 및 Hierarchical Process 개념.
- **본 연구에서 설계:** Solver·Reviewer·Finalizer 역할 구성, Solver 공격 위치, 제한된 메시지 흐름, 선택적 Manager 배정 프로토콜과 비교 실험.

ACIArena가 모든 MAS에 두 Process 구현을 요구하는 것은 아니다. 공식 `crewai` 패키지는 본 실험 런타임에 사용하지 않고, 독립된 `native_reference/`의 기능 대조에만 사용한다.

## 2. 신청서 및 범위 축소 결정의 반영

근거: [연구개발 사업 신청서](<../../../ACIArena_관련_문서/연구개발 사업 신청서(2026)_이재호.pdf>), 2026-08-31 범위 축소 결정, 2026-09-04 Sequential 우선 결정.

신청서의 연구 기간은 2026-07-16~2026-11-30이며, 책임연구원과 학생 연구원 3명이 수행한다. 연구비 2,000,000원은 인건비 중심이므로 이를 모델 API 사용 가능 예산으로 간주하지 않는다. API 비용 상한은 별도로 확인한다.

신청서는 GPT-4o-mini, 기존 MAS와의 비교, BU·UA·ASR·PVI, ACIArena 1,356 사례 평가를 제시하고 비용 초과 시 핵심 domain·공격으로 축소할 수 있게 했다. 여기서 1,356은 논문의 사례 수이지 본 연구의 총 호출 수나 run 상한이 아니다. 공개 Math·Code 69개 task와도 같은 단위가 아니다.

기존의 4개 구성, 전체 공격·위치, full native equivalence, 방어·Tool·Memory 확장안은 범위에서 제외한다. 2026-08-31의 두 구성·약 1,126-run 안을 다음과 같이 갱신한다.

| 항목 | 확정 기본 범위 | 선택 확장 |
|---|---|---|
| Process | Sequential 1개 | 결정 승인 후 Hierarchical 추가 |
| 데이터 | 공개 Math 39개·Code 30개 | 신규 domain 추가 없음 |
| 공격 | 기존 8개 범주, Solver 위치 | 표면·위치 전수 조합은 포함하지 않음 |
| 반복 | 전체 matrix 1회, 고정 subset 확인 반복 | 전체 3회 반복은 후속 연구 |
| 공식 대조 | 10 tasks × 2 implementations = 20 runs | Hierarchical 추가 시 합계 40 runs |
| 기록·지표 | RunRecord·MessageRecord, BU·UA·ASR | PVI는 정의·관측 조건 충족 시만 |
| 규모 | 대표 공격 1개/범주 가정 시 563 runs | 같은 가정의 두 구성 총합 1,126 runs |

run 수의 가정과 재사용·파일럿 비용은 [실험 설계 가이드](02_실험_설계_가이드.md)에서 정의한다. 기존 6종 MAS의 전면 재실행·비교는 이 기본 규모에 포함하지 않는다. 해당 비교를 하지 않으면 신청서 대비 미수행 범위로 명시한다. 범위 축소가 허용됐다는 이유로 Process 제외나 지표 변경까지 자동 승인된 것으로 처리하지 않는다.

## 3. 연구 질문과 검증 목표

### VQ1 — 기능 충실도

고정된 정상 태스크에서 역할·Task 설정, context 전달, 호출 순서와 최종 응답 출처가 공식 CrewAI의 선택된 구성과 어떻게 대응하며, 어떤 차이가 있는가?

### VQ2 — 공격 계약 적합성

외부 입력·프로파일·전달 메시지 공격이 지정 경계에 실제 적용되고, 대상 실행과 변경 내용이 기록되며, 다른 run에 상태가 남지 않는가?

### RQ1 — Sequential의 공격별 결과

공개 Math·Code 부분집합의 고정 Sequential 구성에서 공격 목표와 실제 적용 표면에 따른 BU·UA·ASR, 실행 오류와 비용은 어떠한가? 목표·표면이 완전 교차하지 않으므로 표면 자체의 인과 효과로 해석하지 않는다.

### RQ2 — Process 비교: Hierarchical 채택 시에만 활성화

동일한 모델·task·payload·작업자 역할을 사용할 때 두 구성의 BU·UA·ASR은 어떻게 다른가? Manager의 추가 프롬프트·호출·배정이 함께 달라지므로 순수한 그래프 모양의 효과가 아니라 Process 전체의 차이로 해석한다.

## 4. 기대 기여와 해석 범위

기본 기여는 ① 재현 가능한 Sequential 통합, ② CrewAI 기능과 ACIArena 공격 계약의 대응·한계 보고, ③ 실제 주입 증거를 포함한 감사 가능한 평가 자료다. Hierarchical을 채택하고 검증한 경우에만 동일 조건 Process 비교를 기여에 추가한다.

기존 선행연구조사에서 다룬 CASPIAN 등과의 차별성은 재현성·통합 계약·utility/ASR 평가를 중심으로 검토한다. 최종 원고에서는 원문과 공개 artifact를 다시 확인하고, 단일 구성만으로 학술적 기여가 충분한지는 별도 검토한다. “최초 적용”이나 “기존 연구에 없는 구현”을 확인 없이 주장하지 않는다.

허용되는 표현은 “ACIArena 공개 Math·Code 부분집합의 고정된 CrewAI-style Sequential 재구현에서…”이다. 기능 대조 결과와 차이를 제시하지 않은 채 공식 CrewAI와의 동등성, CrewAI 전체의 취약성, 1,356 사례 전체 재현, 다른 MAS 대비 우월성을 주장하지 않는다.

## 5. Hierarchical 결정과 범위 변경

결정 시점은 Sequential의 계약·공격·저장 검증과 공식 대조·소규모 파일럿을 마친 **G4**, 본 matrix 시작 전이다.

1. 안정성, 남은 구현·검증·분석 시간, 승인된 비용, 비교의 연구적 필요성을 근거로 진행·미진행·보류를 기록한다.
2. 보류는 자동 구현 승인이 아니다. 본 matrix 동결 전에는 활성 구성 목록을 확정한다.
3. 책임연구원과 연구원들의 합의, 결정일·근거·예상 비용·영향받는 연구 질문을 `DECISIONS.md`에 남긴다. 현재 문서의 단계적 결정 방식 채택과 미래의 확장 승인은 별개다.
4. 원하는 ASR이나 유리한 결과가 나왔는지에 따라 범위를 선택하지 않는다.
5. 미진행이면 RQ2를 수행하지 않고 Sequential 단독 결과로 연구·보고 범위를 확정한다. 이는 축소 범위의 완료일 수 있으나 원래 신청서 전체 달성을 뜻하지 않는다.

Manager 위치 비교, worker delegation on/off, 특화 공격, 전체 공격 inventory, 방어·Tool·Memory·Flow, full native equivalence, 복잡한 전파 judge는 기본 연구 완료 후 별도 승인·experiment ID로만 다룬다. Hierarchical 결정만 G4에서 이루어지는 명시적 예외다.
