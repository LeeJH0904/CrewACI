# G7 구현 단계 (1~6단계, 오프라인·무과금)

- 작성일: 2026-09-18
- 대상 단계: G7 CrewAI↔legacy cross-MAS 비교의 **구현(빌드)** 부분
- 전제: G7 사전 확정 종결(§2~§6, `구현문서/G7_사전_확정_진행_사항.md` C1~C10 / `DECISIONS.md` D56~D65)
- 실행 모델: per-invocation 수동, 기존 `benchmark.py` 계승(신규 파일 미신설). MAS 1 × domain 1
  (math|code) × 공격목표 1(hijacking/disruption/disclosure) 슬라이스를 하나씩 벤치·저장 후 분석.

## 전체 흐름에서의 위치

G7은 **① 사전 확정(완료) → ② 구현(1~6단계, 본 문서) → ③ 수집·분석(7~8단계, 유료)** 3층이다.
본 문서의 1~6단계는 **전부 오프라인·유료 호출 0회**이며 지금 바로 진행 가능하다. 유료 실행이
필요한 7~8단계(파일럿·전체 수집·동결)는 사용자가 per-invocation으로 수행하며 본 문서에 포함하지
않는다.

**G6 안전 원칙(D65):** 모든 구현은 G6 동결 산출물(`outputs/g5-v2/`·`outputs/g6/`)을 read-only로
두고, G7 산출물은 `outputs/g7/…`·`g7-…` 버전으로 분리한다. G6 frozen verifier(hash 재검증)가
변경 후에도 PASS해야 한다.

## 1단계 — RunRecord/MessageRecord 스키마 일반화 (무과금)

- **목표:** legacy row가 담길 수 있게 CrewAI 전용 literal을 상위집합으로 넓힌다. 가장 작고
  기반이 되는 작업.
- **작업:** `aciarena/evaluation/records.py`를 in-place 확장(D62).
  - `topology`: `Literal['sequential']` → `Literal['sequential','vertical','horizontal','hierarchical']`
  - `malicious_agent`: `Literal['solver']|None` → `Nonempty|None`
  - `response_agent`: `Literal['finalizer']|None` → `Nonempty|None`
  - `implementation`: `+ 'legacy'`
  - `MessageRecord.phase`: `+ 'turn'`
  - `schema_version`는 `'1.0'` **유지**(순수 확장, 버전 미변경)
  - 공유 필드(attack_category 22·goal 3·surface 3·domain·상태 taxonomy·not_applicable 범위·
    category-goal 일치·증거 플래그 요구)는 그대로 둔다.
- **산출물:** 확장된 `records.py`.
- **게이트:**
  - 기존 CrewAI 행이 그대로 `model_validate` 통과(상위집합이라 하위호환).
  - **G6 frozen verifier PASS** — `outputs/g6/…/g6_artifact_manifest.json`의 hash 재검증 및
    G6 재감사가 변함없이 통과(records.py는 G6 analysis_sources에 없음).
- **근거:** D62, `구현문서/G7_사전_확정_진행_사항.md` C7.

## 2단계 — G7 manifest·매핑 테이블 (무과금)

- **목표:** "어느 MAS를, 어느 domain에서, 어느 공격을, 어느 agent에" 돌릴지를 **결과 보기 전에**
  결정적으로 고정한다.
- **작업:**
  - `manifests/g7/systems.json`: 비교 대상 MAS(논문 6종 + CrewAI, MAD 제외), MAS별 지원
    domain(MetaGPT code-only·나머지 both), topology 라벨, 최종 응답 source.
  - `manifests/g7/targets.json`: 공격목표별 target agent = 논문 Appendix I Table 5(Math,
    GPT-4o-mini) worst-case, code는 Math값 재사용, MetaGPT는 `metagpt.sh` 관례.
  - **식별 매핑 테이블(D63-ii):** legacy 익명 task(query+gt) → manifest `task_id`(동일 소스
    `aciarena_math/code.json` 순서·내용 기반 결정적 정렬), legacy 공격 클래스 → manifest
    `attack_id`.
- **산출물:** `manifests/g7/{systems,targets}.json`, 매핑 테이블.
- **게이트:** dry-run에서 예정 matrix가 결정적으로 재현되고 모델 호출 0회. 22개 공격 class가
  각 지원 domain에서 단일 ID로 선택.
- **근거:** D58/D59/D63, C3·C4·C8.

## 3단계 — legacy recording 어댑터 (무과금, 핵심)

- **목표:** legacy 실행·verify를 재사용하고 그 위에 recording 계층을 후크로 이식해, CrewAI와
  **동일한 per-row 스키마**를 생산한다((A) 방식).
- **작업:** legacy 실행 경로(`aciarena/evaluation/task_executor.py`·`evaluation_suite.py`)를 감싸
  RunRecord/MessageRecord를 emit. 필드는 3버킷(C8):
  - **직결:** `raw_response`(args 최종 응답)·`ground_truth`·`prompt/completion_tokens`
    (`get_token_usage`)·`attack_goal`(suite)·`attack_surface`(공격 base클래스 AdvInput→
    instruction·MaliciousAgent→agent·MessagePoison→message)·`malicious_agent`
    (`attack.malicious_agents`)·메시지(MASLogger `session["turns"]`).
  - **파생:** `response`(CrewAI와 동일 normalizer)·`payload_hash`·`response_agent`(MAS별 최종
    source)·`topology`(MAS별 상수)·식별·`config_hash`·timestamps.
  - **신규 구축(실질 작업):**
    1. `task_id`·`attack_id` 매핑 적용(2단계 테이블).
    2. `target_invoked`/`payload_injected` **계측**(`attack.run()` 효과·대상 agent 호출 관찰).
    3. **오류 격리**(`execute()`를 try/except로 감싸 `model_error`/`timeout`/`protocol_error`
       row·partial trace 생산) + **상태 taxonomy**: legacy `verify()`는 0/1뿐이므로 실행 오류가
       아니면 `utility_status`/`attack_status`를 `valid`+bool로 기록(D63-i). unknown/na는 CrewAI만큼
       구분하지 않으며, 이 진단 해상도 비대칭은 report에 명시. `llm_call_count` 미추적은
       `usage_missing_calls`로 공개.
- **산출물:** legacy 어댑터 모듈 + `RunWriter`로 `runs.jsonl`/`messages.jsonl` 저장.
- **게이트:** 세 표면의 target 도달·payload 주입 증거가 남고, MAS별 final response source가 실제
  출력과 일치하며, 빈 출력·모델 오류·timeout·Judge 오류·저장 오류가 서로 다른 상태로 기록된다.
- **근거:** C7·C8 / D62·D63.

## 4단계 — `benchmark.py` 확장 (무과금)

- **목표:** per-invocation 진입점에서 legacy 슬라이스가 G7 형식으로 저장되게 배선.
- **작업:** 기존 `benchmark.py`(`--mas`·`--task_domain`·`--suite`=공격목표·`--malicious_agents`
  =target agent)의 legacy 경로가 3단계 어댑터를 사용해 `outputs/g7/…`에 per-row를 저장하도록
  확장. dry-run 기본, config-hash 기반 resume, 종단 audit 유지.
- **산출물:** 확장된 `benchmark.py`(CrewAI recorded 경로는 그대로, legacy 경로에 recording 추가).
- **게이트:** `--execute` 없는 0-call dry-run 기본 동작, valid false resume·허용 retry·
  duplicate/gap/config drift audit 동작.
- **근거:** D59-⑤·D64, C9.

## 5단계 — 공통 집계기 확장 + G7 report (무과금)

- **목표:** CrewAI와 legacy 원본을 **같은 규칙**으로 재계산하고 G7 보고서를 생성한다.
- **작업:** `aciarena/evaluation/aggregation.py`(D55, generic mapping 입력)에 legacy row를 투입
  (집계 로직 자체는 재사용). G7 전용 분석/리포트 버전(`g7-…`)과 `outputs/g7/…` 경로로 산출.
  - **헤드라인:** 논문 규칙(단순 비율, empty/error/미주입=0, NA 제외 안 함) — **도메인별 표
    (Math 5종 / Code 6종)** 에 각 MAS와 CrewAI를 나란히, **UA·ASR 쌍**(트레이드오프)으로.
  - **진단:** valid-only 분해를 별도 보고(legacy는 사실상 헤드라인과 동일, D63-i).
  - **불확실성:** 시스템별 task-cluster bootstrap CI(위치 제시). **paired 검정·순위표 없음**,
    "X가 Y보다 안전" 식 서술 지양(D61).
- **산출물:** G7 report(JSON/MD/CSV) + artifact manifest, `outputs/g7/…`, `g7-…` 버전.
- **게이트:** 동일 정책(헤드라인·진단 2레이어)이 CrewAI 원본과 모든 legacy 원본에 적용됨을
  fixture로 검증.
- **근거:** D30·D54·D61 / C6.

## 6단계 — 오프라인 acceptance 검증 (무과금)

- **목표:** 유료 수집 전에 mock LLM으로 파이프라인 전체를 검증한다.
- **작업:** 아래 항목을 오프라인 회귀로 통과.
  - 필수 legacy MAS(논문 6종)가 mock LLM으로 최소 정상 run 완료.
  - Math·Code 지원 matrix가 manifest와 일치(MetaGPT code-only 등 실제 domain 반영).
  - 세 표면 증거·MAS별 final source·상태 구분(빈 출력/오류/timeout/Judge/저장)·resume·retry·
    audit·0-call dry-run 결정적 재현.
  - **G6 frozen verifier가 여전히 PASS**(1단계 변경 이후 재확인).
- **산출물:** 통과한 오프라인 테스트 스위트.
- **게이트:** `구현문서/G7_사전_확정_필요_사항.md` §4.3·§6.3의 검증 항목 전부 통과.
- **근거:** §4.3·§6.3 / C7.

## 단계 의존·순서

```
1(스키마) → 2(manifest·매핑) → 3(어댑터, 핵심) → 4(benchmark.py 배선)
         → 5(집계기·report) → 6(오프라인 acceptance)
```

1단계는 나머지 전부의 전제(스키마가 legacy 값을 받아야 함)이고, 3단계가 실질 작업량의 대부분이다.
6단계 통과 후에야 7단계(유료 파일럿)로 넘어간다.

## 완료 후

6단계까지 통과하면 구현이 끝나고, 이후는 사용자 유료 실행이다.

- **7단계(파일럿):** 소수 슬라이스 실모델 end-to-end 확인 + MAS별 실 토큰/비용 감각. 사전 비용
  산정·게이트 없음(D64), dry-run 기본 + 사후 usage 기록.
- **8단계(전체 수집·동결):** CrewAI 포함 전 슬라이스 실행·저장 → 공통 집계 → G7 report 동결.
  완료 정의는 `00_구현_가이드.md` §7(Cross-MAS 비교 완료)을 따른다. **G7 완료 = 전체 연구 완료**
  (신청서 "기존 6종 대비 CrewAI 위치" 충족).
