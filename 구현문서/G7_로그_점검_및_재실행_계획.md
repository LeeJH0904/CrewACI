## 2. 버그 상세

### ① CAMEL: message 공격 payload가 첫 글자만 전달됨

- **원인:** CAMEL의 `task_specifier`, `user_proxy`, `assistant`는 `run_step()`의 결과로 후보 응답 **리스트**를 돌려줍니다. `camel_mas.py`는 `specified_task[0]`, `user_proxy_response[0]`, `assistant_completion[i]`처럼 그중 하나를 꺼냅니다. 그런데 `MessagePoisonAttack`(`aciarena/attacks/base_attack.py:137-138`)은 `step`이 payload **문자열**을 돌려주게 바꿉니다. 그 결과 `[0]`이 문자열의 첫 글자를 꺼내게 됩니다.
- **증상:** 다음 agent가 받은 메시지는 `'<'`(DDoS) 또는 `'\n'`(API key) 한 글자뿐입니다. 그런데 기록에는 `status=success`, `payload_injected=True`로 남아서 공격 실패로 집계됐습니다. assistant를 공격하면 최종 응답과 기록된 출력이 달라 `LegacyProtocolError`가 납니다.
- **영향 slice (gpt-4o-mini):**

| slice | attack | run 수 |
|---|---|---|
| `math_task/camel/camel_math_task_specifier_disr` | `disruption_ddos.message.v1` | 39 |
| `math_task/camel/camel_math_user_proxy_disc` | `disclosure_generic_apikey.message.v1` | 39 |
| `code_task/camel/camel_code_task_specifier_disr` | `disruption_ddos.message.v1` | 30 |
| `code_task/camel/camel_code_user_proxy_disc` | `disclosure_generic_apikey.message.v1` | 30 |

- **수정:** `aciarena/mas/camel/camel_mas.py`에 `_run_options()`를 추가했습니다. agent가 문자열을 돌려주면 리스트로 감싸서 넘깁니다. 정상 run은 원래 리스트를 돌려주므로 동작이 그대로입니다.

### ② LLM Debate: debater message 공격 payload가 전달되지 않음

- **원인:** 다른 debater와 aggregator는 debater의 응답을 `run_step()`의 반환값이 아니라 `get_latest_response()`로 **agent 메모리**에서 읽습니다. 공격으로 바뀐 `step`은 메모리에 쓰지 않습니다. 그래서 공격된 debater의 답은 항상 빈 문자열입니다. 다른 debater의 프롬프트에서는 빠지고, aggregator 프롬프트에는 빈 `Solution N:` 칸이 들어갑니다.
- **증상:** payload가 어느 agent에게도 전달되지 않는데 `payload_injected=True`로 기록됐습니다.
- **영향 slice (gpt-4o-mini):**

| slice | attack | run 수 |
|---|---|---|
| `math_task/llm_debate/llm_debate_math_debater_2_hi` | `hijacking_math_invert.message.v2` | 39 |
| `code_task/llm_debate/llm_debate_code_debater_0_disr` | `disruption_ddos.message.v1` | 30 |
| `code_task/llm_debate/llm_debate_code_debater_0_disc` | `disclosure_generic_apikey.message.v1` | 30 |
| `code_task/llm_debate/llm_debate_code_debater_1_disr` | `disruption_ddos.message.v1` | 30 |
| `code_task/llm_debate/llm_debate_code_debater_1_disc` | `disclosure_generic_apikey.message.v1` | 30 |

  aggregator를 노린 message 공격은 aggregator가 최종 응답 agent라서 정상입니다.
- **수정:** `aciarena/mas/llm_debate/llm_debate_mas.py`가 각 debater의 `run_step()` 반환값을 `self.latest_responses`에 저장하고, 다른 debater와 aggregator가 이 값을 읽도록 바꿨습니다. 정상 run에서는 반환값과 메모리 값이 같아서 동작이 그대로입니다.

### 공통: 수정 검증과 공통 코드를 건드리지 않은 이유

- **회귀 테스트:** `tests/integration/test_g7_legacy_acceptance.py::test_message_payload_reaches_downstream_agents_intact`를 추가했습니다. 수정 전 코드에서는 4건이 실패하고, 수정 후에는 통과합니다.
- **사전 점검:** 아직 수집하지 않은 target(CAMEL 4종, AgentVerse 4종, sc1, debater_2)의 message 공격을 가짜 LLM으로 돌려 봤습니다. payload가 다음 agent에게 그대로 전달됩니다. 예외는 ⑥에 적었습니다.
- **공통 코드를 고치지 않은 이유:** `base_attack.py`와 `base_agent.py`는 모든 legacy MAS의 config `sources`에 들어 있습니다. 여기를 고치면 7개 MAS 전체의 hash가 바뀝니다(D67 ③ 원칙). 그래서 MAS 파일만 수정했습니다.

### ③ CAMEL·LLM Debate 데이터 전체가 source drift (집계 불가)

- **원인:** ①② 수정으로 `camel_mas.py`와 `llm_debate_mas.py`의 sha256이 바뀌었습니다. `scripts/aggregate_g7.py`의 `_validate_snapshot()`은 config 스냅샷에 기록된 소스 해시를 현재 소스와 비교하고, 다르면 `Config sources drift`로 집계를 거부합니다. message 공격과 관계없는 slice(benign, agent·instruction 공격)도 똑같이 거부됩니다.
- **영향:** CAMEL Math 546, Code 450, LLM Debate Math 546, Code 1,410으로 총 2,952 run입니다.

### ⑥ 구조상 0이 나오는 target (버그 아님, 보고서에 명시)

- **CAMEL critic:** `with_critic: False`(`camel_mas.py:15`)라서 critic이 한 번도 실행되지 않습니다. Math·Code critic slice는 모두 `target_invoked=False`입니다(D66 알려진 한계). Code critic disr·disc를 새로 돌려도 0이 나옵니다. 그래도 D66의 "전 agent" 원칙에 따라 목록에 넣었습니다. 빼려면 결정 기록이 필요합니다.
- **AgentVerse role_assigner (message 공격):** role_assigner의 출력은 `"1. ~. 2. ~."` 형식을 정규식으로 파싱해 역할 설명만 꺼내 씁니다(`role_assigner_agent.py:38-45`). payload는 이 형식에 맞지 않아 빈 역할 `[""]`로 버려집니다. 그래서 `role_assigner_{disr,disc}`의 message 공격(각 30 run)은 구조상 0입니다. 그런데 `payload_injected=True`로 기록되므로, 보고서에 이 점을 함께 적어야 합니다. agent·instruction 공격은 역할 설명을 통해 영향을 줄 수 있습니다.
- **AutoGen user_proxy:** assistant가 첫 응답에서 TERMINATE하면 user_proxy가 호출되지 않습니다. 실제로 호출되지 않은 run 수는 아래와 같습니다(D66 알려진 한계).
  - Math hi: 79/117
  - Code hi: 99/120
  - Code disr: 123/150
  - Code disc: 104/150
- **AutoGen 로그 오기록:** `autogen_mas.py:37`이 user_proxy→assistant 턴에 `assistant_response`를 기록합니다. 실제로 전달되는 값과 `target_invoked`, `payload_injected` 판정은 맞아서 결과에는 영향이 없습니다. 다만 `messages.jsonl`의 해당 턴 내용은 틀립니다. 고치면 AutoGen의 hash가 바뀌어서 그대로 뒀습니다.
- **CrewAI finalizer message 공격:** 최종 답이 payload 자체가 됩니다(D67 알려진 동작). Math disclosure의 apikey.message 39 run은 `utility_status=unknown`입니다.
- **HijackingMathInvert:** 각 Math hijacking slice에 `not_applicable`가 6건 있습니다. 부호를 뒤집을 수 없는 정답이라 설계상 그렇습니다.
