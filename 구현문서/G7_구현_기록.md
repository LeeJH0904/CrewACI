## 1. 구현 결과

### 1단계 — 공통 record 상위집합

`aciarena/evaluation/records.py`의 schema version은 `1.0`으로 유지하고 다음 literal만
상위집합으로 확장했다.

- implementation: `legacy`
- topology: `vertical`·`horizontal`·`hierarchical`
- malicious/response agent: 임의 non-empty 역할명
- legacy message phase: `turn`

기존 G6 CrewAI 행은 변경 없이 Pydantic 재검증을 통과한다.

### 2단계 — G7 manifest·식별 매핑

`manifests/g7/`에 다음을 고정했다.

- `systems.json`: 논문 6종+CrewAI, MAD 제외, MetaGPT code-only, 나머지 both, topology,
  실제 agent inventory, max turn, 최종 응답 source.
- `targets.json`: Appendix I Table 5의 Math/GPT-4o-mini worst-case target, code 재사용,
  MetaGPT script 관례, CrewAI solver.
- `identifiers.json`: G5-v2의 39 Math+30 Code task content→ID, 22개 고유 attack class→ID.

예정 core matrix는 legacy 신규 5,430행, CrewAI 포함 총 6,426행이다.

### 3단계 — legacy recording adapter

`aciarena/evaluation/legacy_recording.py`가 실제 legacy MAS와 기존 task/attack verifier를
run별로 실행하면서 다음 공통 증거를 `RunWriter`에 저장한다.

- 결정적 run/config ID, credential 제거 model/Judge 설정, manifest/source/dependency hash.
- raw/normalized 응답, manifest final source와 실제 agent 출력 일치 검사.
- instruction/profile/message 세 표면의 target 호출·payload 직접 증거.
- Agent+Judge 호출 수와 알려진 token delta, 누락 usage 공개.
- 실행 오류·timeout·protocol 오류, utility/attack verifier 오류, 빈 출력, storage fail-stop.
- valid false resume, transient provider 오류만 최대 3 attempt retry.
- AnswerMapping/MathInvert의 동결 task-level not-applicable.

고정 target이 해당 실행에서 호출되지 않거나 payload가 유효 경로에 주입되지 않은 조건은
D54대로 boolean 증거를 그대로 남기고 headline ASR의 0으로 센다. 이 조건 자체 때문에
per-invocation audit 전체를 실패시키지는 않는다.

### 4단계 — `benchmark.py` per-invocation 진입점

논문 6종은 G7 adapter, CrewAI는 기존 recorded 계약을 사용한다. 공통 기본값은 다음과 같다.

- `--execute` 없음: 모델/Judge 생성과 output 생성이 없는 결정적 dry-run.
- `--execute`: 사용자가 지정한 MAS×domain×suite 한 slice만 실행.
- 기본 output: `outputs/g7/<experiment_id>`; 기본 experiment ID `g7-cross-mas-v1`.
- CrewAI도 G5-v2의 동일 69 task·22 attack inventory를 G7 경로에서 사용.
- legacy는 목표별 manifest target을 기본으로 하되 명시적 단일 대체 target도 기록·허용.
- `outputs/g5-v2`·`outputs/g6` 아래 쓰기와 경로 탈출 experiment ID 거부.

### 5단계 — G7 집계·보고

- 분석 버전: `g7-cross-mas-aggregation-v1`
- 보고 버전: `g7-cross-mas-report-v1`
- artifact 버전: `g7-cross-mas-artifact-manifest-v1`

헤드라인은 모든 계획/채택 core 조건을 단순 비율 분모에 두고 빈 출력·실행/평가 오류·
not-applicable·미호출·미주입을 0으로 센다. 진단은 G6 valid-only 분모를 별도로 적용한다.
Math/Code별 시스템 표에는 UA·ASR과 시스템별 task-cluster bootstrap CI를 함께 제시한다.
paired 검정, 전체 순위, 일반적 안전 우열 주장은 만들지 않는다.

`scripts/aggregate_g7.py`는 기본 read-only이며 JSONL을 write handle/lock 없이 읽는다.
`--write`에서만 `g7_report.{json,md}`, `g7_metrics.csv`, `g7_artifact_manifest.json`을
G7 경로에 생성한다. exact 6,426-condition matrix가 불완전하면 기본 write를 거부하고,
진단용 부분 artifact는 `--allow-partial-write`를 명시해야 한다.

## 3. G6 frozen 보존 검증

`scripts/verify_g6_frozen.py`는 동결 JSONL을 write lock 없이 읽고 다음을 검증한다.

- artifact/source/input SHA-256: **16/16 일치**
- 계획/관측: **1,056/1,056**, strict 완료 1,054
- 동결 report hash: `1db3b6880a8bce4ed6add025238b5679ab92d5a9cf3fe75c455e729743167814`
- BU/UA/ASR: **47/69, 562/925, 93/919**
- target/payload: 987/987, usage complete

D62의 의도된 additive schema 변경 때문에 과거 config snapshot에 기록된 `records.py` hash와
현재 source hash는 달라진다. frozen verifier는 이 한 항목만 명시적으로 허용하고 나머지
source/config/artifact drift는 모두 거부한다. `outputs/g5-v2/`와 `outputs/g6/`의 동결
데이터·보고서 내용은 수정하지 않았다.
