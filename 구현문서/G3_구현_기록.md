# G3 공식 CrewAI↔재구현 Sequential calibration 구현 기록

작성일: 2026-09-10

## 상태

**완료.** authoritative `g3-sequential-calibration-v2`에서 실제 Bionic 10 tasks × 2
implementations = 20 runs와 공통 verifier 비교를 수행해 G3 Gate를 통과했다.

## 확정 계약

- 공식 참조: `crewai==1.15.21`, Python 3.10 별도 exact-lock 환경.
- 모델: 양쪽 모두 G0 개발용 Bionic `qwen2.5-0.5b-instruct`, temperature 0.0,
  max tokens 1,024, seed 42 요청. paid API 비용 0.
- 구성: Solver→Reviewer→Finalizer, `Process.sequential`, delegation/tools/Memory/Planning
  비활성. 공식 기본 executor와 공식 prompt scaffolding을 보존한다.
- 표본: `manifests/calibration_tasks.json`의 Math 5·Code 5 고정 태스크.
- 해석: 작은 기능 대조이며 완전한 공식 동등성 또는 성능 동등성 검정이 아니다.

## 구현

- `calibration_contract.py`: 선택/hash 검증, 공통 role·Task 계약, credential 제거,
  append-only JSONL과 중복 방지.
- `crew_factory.py`: 공식 Agent/Task/Crew 생성, LLM hook으로 실제 입력·응답 기록,
  Task 출력·Finalizer source·usage·시간·오류 보존, task당 180초 상한.
- `reconstructed_adapter.py`: 같은 태스크의 재구현 실행과 실제 세 LLM call 기록.
- `run_calibration.py`: 구현별 독립 실행·resume·dry-run.
- `compare_calibration.py`: 원본을 변경하지 않고 공통 Math/Code verifier 적용,
  context/source·완료·parse·utility disagreement 보고.
- `requirements.lock`: 공식 참조 환경 140개 패키지 exact freeze. 메인 `.aciarena`와
  격리되어 Gemini 등 본 벤치 의존성을 다시 추가하지 않는다.

## 검증

- main unit 71개 통과(G3 신규 8개 포함), 기존 integration 40개 통과(메인 총 111개).
- 공식 CrewAI 별도 환경 native smoke 1개 통과. 로컬 mock OpenAI endpoint를 통해
  공식 기본 executor까지 실행하고 native의 실제 요청 model id가 공통 config와 일치함을
  확인했으며 외부 모델 API 호출은 없다.
- dry-run에서 고정 task 선택과 구현별 출력 경로를 확인했다.
- HumanEval parse는 실제 verifier처럼 원본 prompt와 추출 completion을 결합하며, parse
  unknown도 완료 실행 분모에서 제외하지 않는 회귀를 확인했다.

## 실제 calibration 결과

- reconstructed/native 완료: 각각 10/10.
- context 증거와 Finalizer source: 양쪽 각각 10/10.
- parse: reconstructed 10/10, native 9/10, 차이 10 percentage points.
- utility: 양쪽 모두 성공 0건. 비교 가능한 9쌍 disagreement 0건, native `code_0006`
  문법 오류 한 쌍은 비교 불가.
- 실행량: 양쪽 각 30 calls. reconstructed 25,453 tokens/76.054초, native 22,999
  tokens/72.959초.
- 판정: 가이드의 완료·context/source·parse-gap 기준을 충족해 Gate PASS. 작은 로컬 모델의
  utility가 모두 실패했으므로 성능 동등성 또는 공식 CrewAI 전체 동등성을 뜻하지 않는다.

최초 `g3-sequential-calibration-v1`은 실제 context가 있었지만 multiline 문자열을 JSON
escape 상태에서 검색한 검사기 결함으로 FAIL했다. 원본을 덮어쓰지 않고 진단 이력으로
보존했으며, 생성 계약에서 분석기 source를 분리하고 분석 버전/hash를 보고한 뒤 v2를
새로 실행했다.
